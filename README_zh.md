# Auto Script for GitHub Setup and Push

[English](README.md)

Auto Script for GitHub Setup and Push 是一个面向所有人的集中式 Bash 工具，让本地改动经过更少操作和更可靠的身份核对后上传到 GitHub。所有复杂流程统一由 `git-auto.sh` 维护，每个项目都使用同一套简洁的 `g.sh` 操作入口。

日常只需记住四个入口：

- `./g.sh`：识别当前 Git 仓库，核对 GitHub 账号与目标仓库，检查改动，然后提交并上传。
- `./g.sh new`：新增或导入 GitHub 账号，并可继续将其用于当前项目。
- `./g.sh update`：GitHub 用户名、仓库名或仓库归属变化后，同步本机设置。
- `./g.sh menu`：打开账号、项目核对、偏好设置和高级工具。

SSH 身份、账号核验、项目提交身份、发布提交说明、上游分支和严格推送身份均由脚本在内部处理。

## 整体结构

整个项目由一个中央引擎、一份私人配置和每个项目各自的启动器组成：

```text
git-auto/
|-- git-auto.sh
|-- g.sh              公开且可以直接复制的轻量启动器
|-- README.md
|-- README_zh.md
|-- CHANGELOG.md
|-- CHANGELOG_zh.md
|-- tests/
|-- private/          仅保留在本机；自动创建且不会进入 Git
|   `-- config.txt
`-- sidenote/         本机 Agent 笔记；不会进入 Git

your-project/
|-- g.sh              自动生成的轻量启动器；仅保留在本机
`-- 项目文件...
```

`git-auto.sh` 是唯一的完整实现。不再区分公开脚本和个人脚本，也不在可执行代码中重复保存账号区块。中央引擎更新一次，所有启动器都会使用新功能。

## 第一次使用

把公开项目放在准备长期保存中央脚本的位置，然后运行：

```bash
chmod +x git-auto.sh
./git-auto.sh
```

第一次在交互式终端中运行时，脚本会询问一次界面语言，并把选择写入 `private/config.txt`。中央管理菜单可以把 `g.sh` 复制到指定项目。仓库根目录也直接提供同一份公开启动器，因此手动复制同样可以使用：

```bash
cp g.sh /path/to/your-project/g.sh
```

以后进入具体项目，只使用下面四个短命令：

```bash
./g.sh
./g.sh new
./g.sh update
./g.sh menu
```

不需要设置 Shell alias、修改 PATH、安装软件包，也不会创建额外的应用专用用户配置目录。需要提交和上传中央仓库本身时，直接运行其中由 Git 跟踪的 `./g.sh`。

## 中央管理菜单

在中央文件夹中运行 `./git-auto.sh` 会打开管理菜单，可用于：

- 为指定项目创建或修复 `g.sh`。
- 把 GitHub 账号添加到共享私人配置。
- 核对每个已保存 GitHub 账号实际使用的 SSH 密钥；验证失败时给出明确原因和下一步选项。
- 修改所有项目共用的界面语言和显示模式。
- 进入高级工具，包括历史发布版本导入。

在中央文件夹中运行 `./git-auto.sh new` 可以直接进入账号设置。直接运行 `./git-auto.sh` 只负责中央管理；所有项目操作都使用 `./g.sh`，中央仓库本身也不例外。

## 轻量级项目启动器

公开的 `g.sh` 不包含 GitHub 账号、SSH、版本、提交或历史重建业务逻辑。它会把自身所在文件夹作为项目根目录，并依次从项目本地 Git 设置、当前文件夹、相邻或上级目录中的 `git-auto/`、常见用户目录和 `PATH` 寻找中央脚本。全部方式都没有找到时，才会询问 `git-auto.sh` 的位置。

中央仓库根目录的 `g.sh` 由 Git 正常跟踪，绝不会加入该仓库的忽略规则。中央菜单把它复制到其他项目后，只会将那个项目中的副本写入 `.git/info/exclude`，不会改动团队共享的 `.gitignore`。项目完成配置后，中央脚本路径保存在该项目自己的 `.git/config` 中；`g.sh` 本身不含任何个人路径。

中央文件夹移动后，启动器会重新搜索，并可用中英文接受用户粘贴的新路径。也可以从新位置打开中央菜单修复项目启动器，无需重新设置项目或账号。

## 私人配置

所有个性化应用状态都保存在 `git-auto.sh` 旁边被 Git 忽略的 `private/config.txt`：

```text
language: zh
display-theme: auto

username: johnjoe
email: 123456+johnjoe@users.noreply.github.com

username: alice
email: alice@example.com
```

每个字段独占一行，账号之间用空行分隔。每个账号只有 GitHub 用户名和提交邮箱，提交显示名始终由 GitHub 用户名自动确定。

中央引擎会自动创建 `private/`，并把目录和配置文件权限分别限制为只有当前用户可以访问和读写。保存时采用原子替换，不会在其中写入私钥、密钥口令、访问令牌或登录密码。

其他人使用公开项目时，也会自动得到各自独立且被忽略的 `private/` 文件夹，不再需要制作个性化脚本副本。

## 输入方式

- 需要从列表中选一项时，直接输入该项前面的数字，例如 `1`、`2`、`3`。
- 输入 `0` 即可返回或取消，不会选中任何一项。
- 只需确认是否执行某项已经说明清楚的操作时，界面会直接询问“是”或“否”，无需记忆额外的数字含义。

## 运行 g.sh 后会发生什么？

默认流程完全依据项目当前状态推进：

1. 把 `g.sh` 所在文件夹作为准确的项目根目录。
2. 首先判断这里是否已经是 Git 仓库。若已经初始化，现有提交、分支、暂存内容和远端设置全部保留，也不会再次执行 `git init`。若尚未初始化，脚本会先说明 `git init` 此时只创建本地记录，再执行初始化。
3. 如果当前处于 detached HEAD、仍有未解决冲突，或 merge、rebase、cherry-pick、revert 尚未完成，立即停止，不修改项目文件。
4. 读取 `origin`。如果地址使用 `github800` 这类 SSH 主机名，优先核对该主机名指定的密钥和实际 GitHub 账号。只有 `origin` 无法确定仓库时，才询问仓库地址。
5. 依次优先采用当前仓库已保存的账号、经 GitHub 验证的 origin 账号和明确的仓库所属账号。只有无法安全判断时，才显示用户名供用户选择。
6. 使用选定私钥读取准确的目标仓库；验证通过后，只把提交作者、账号、密钥、中央脚本路径和 `origin` 保存到当前仓库自己的本地 Git 设置中。
7. 暂存前先展示 `git status --short`。用户可以采用建议提交说明、自行填写，或输入 `:cancel` 停止。只有确认说明后，脚本才执行 `git add -A`。
8. 创建提交并展示内容，然后使用唯一一把已经验证的密钥上传当前分支。普通流程绝不强制推送。

工作区没有改动时不会制造空提交。仓库既没有提交也没有项目文件时会直接结束，不会尝试上传。在提交说明处取消发生在 `git add -A` 之前，原本已经暂存的内容也会保持原样。

## GitHub 账号设置

`./g.sh new` 和中央账号菜单遵循同一套账号规则：

1. 当前项目的 SSH `origin` 对应一个尚未保存的账号时，先核对该主机名和密钥。GitHub 能够确认账号后，用户只需确认提交邮箱。
2. 否则扫描 `~/.ssh/config` 及其 `Include` 文件，找出最终 `HostName` 为 `github.com` 的具体配置。
3. 每把不同的候选密钥只验证一次，由 GitHub 返回其实际登录的用户名。
4. 发现尚未写入 `private/config.txt` 的已验证账号时，询问是否保存。
5. 没有可复用身份时，只询问 GitHub 用户名和提交邮箱，并在创建前明确列出将增加的私钥路径和 SSH 主机名。
6. 用户确认后才创建独立 ED25519 密钥，再引导用户把公钥添加到正确账号；GitHub 返回的用户名完全一致后才保存账号。

新 SSH 主机名默认使用 `github-USERNAME`。遇到冲突时会自动尝试 `-1`、`-2` 及后续数字。每个新建账号使用不同私钥；现有密钥只有在 GitHub 确认具体用户名后才会复用。网络验证失败时不会静默创建替代密钥，而是先显示返回结果，让用户选择重试。

隐私提交邮箱建议采用 GitHub 当前的 `ID+USERNAME@users.noreply.github.com` 格式，也可以填写已经在 GitHub 验证的其他邮箱。

## 多账号保护

共享私人配置让所有项目都能使用已经配置的账号，但每个仓库每次推送仍然只允许使用一个明确账号。

项目专属信息只保存在该仓库的 `.git/config`：用户名、邮箱、SSH 连接名、密钥文件和规范化后的 `origin`。每次网络操作前，脚本都会创建临时 SSH 包装程序，启用 `IdentitiesOnly=yes` 并固定选定私钥，SSH Agent 中的其他密钥不能静默成为备用身份。

组织仓库会绑定到明确选择的个人账号，不会把组织名称误当作登录身份。

## 仓库地址输入

仓库输入框可以识别并规范化常见 GitHub 格式：

```text
owner/repository
owner/repository.git
github.com/owner/repository
https://github.com/owner/repository
https://github.com/owner/repository/tree/main
https://github.com/owner/repository/blob/main/README.md
git@github.com:owner/repository.git
ssh://git@github.com/owner/repository.git
git://github.com/owner/repository.git
git clone https://github.com/owner/repository.git
gh repo clone owner/repository
```

查询参数、页面锚点、末尾斜杠、`.git` 和仓库内部页面路径都会自动去除。非 GitHub 地址会被明确拒绝，不会静默改写。

## 用户名或仓库发生变化

在 GitHub 上完成用户名修改、仓库改名或仓库转移后，在受影响项目中运行 `./g.sh update`。

这个流程以 GitHub 上已经完成更名或转移为前提。脚本先询问哪项内容发生了变化，只收集相关的新信息。写入前会确认原有密钥现在登录的是新用户名，并核实该账号能够读取准确的新仓库；最后还会逐项列出即将修改的本机文件和 Git 设置。

用户名变化时继续使用原密钥；需要新 SSH 主机名时自动生成无冲突的用户名形式，同时保留旧主机名，避免影响其他项目。脚本还会同步共享私人账号记录、当前仓库的提交身份和 `origin` 拉取与推送地址。整个 update 流程不会修改或上传项目文件、分支、提交记录和 GitHub 远端仓库；在最终确认处取消时，`private/config.txt`、`~/.ssh/config` 和当前仓库的 `.git/config` 都保持不变。

## 提交说明和发布版本

每次真正创建提交前仍由用户确认。中央引擎会先展示工作区状态，再给出建议说明；确认后才执行 `git add -A`，随后展示暂存摘要并创建提交。

已有仓库按照以下顺序发现发布版本：

1. 根目录 `package.json` 中的有效版本。
2. 根目录 `CHANGELOG`、`CHANGELOG.md` 或 `CHANGELOG.txt`。
3. 根目录其他 `CHANGELOG*` 语言版本；存在差异时采用最高有效版本。
4. 根目录没有可用变更日志时，递归扫描项目自有的 `CHANGELOG*` 并采用最高有效版本。
5. 根目录 `VERSION*` 文件。
6. 递归 `VERSION*` 文件。
7. 回退为 `Update`。

解析支持新版本在顶部或底部、常见英文和中文日期、预发布版本、构建信息、可选 `v` 前缀、方括号和多种 Unicode 破折号。递归查找会排除依赖、缓存、虚拟环境、构建和覆盖率目录。

## 导入历史发布版本

高级菜单可以从一组完整版本文件夹重新建立原本缺失的线性 Git 历史。

脚本会发现或接收版本映射，按照 SemVer 排序，并在临时仓库中为每个版本创建一个完整的 `Release X.Y.Z` 快照提交。新版已经删除的旧文件不会残留在新版快照中。正常隐藏文件和被忽略文件会保留，每一层的 `.git` 和 `.DS_Store` 都会排除。

存档版本缺少根目录 `.gitignore` 时，用户可以在终端直接粘贴一份通用规则。它只会添加到缺失的重建快照，不会写回原始版本文件夹。

流程会检查疑似敏感文件和超大文件，可创建轻量版本标签，展示 `git log --oneline --reverse`，并在上传前验证选定的 GitHub 身份。替换已有远端 `main` 必须明确确认，并使用精确的 `--force-with-lease`。脚本不会创建备份分支，也不会改动其他远端分支。

快照复制由中央引擎自行实现，不依赖 `rsync`。

## 语言、显示和无障碍体验

第一次运行默认选择英文，也可使用完整本地化的中文界面。选定语言统一应用于项目命令、中央管理、更新流程、高级工具、说明、提醒和错误信息，并可从任一菜单修改。

显示模式支持自动、深色、浅色和无颜色。自动模式优先读取终端背景信息，在 macOS 上也会参考系统外观。设置 `NO_COLOR` 或非交互输出时会关闭颜色。

整个界面只使用纯文字状态标签，不输出 Emoji 表情符号。

## 安全与本机状态

中央引擎只写入当前流程确实需要的位置：

- `private/config.txt`：共享的个人偏好与账号基本资料。
- `~/.ssh`：GitHub SSH 密钥和配置。
- 目标仓库的 `.git/config` 与 `.git/info/exclude`：本地账号绑定和启动器排除。
- 临时目录：严格 SSH 包装程序和历史版本重建仓库。

脚本不会使用其他应用专用配置目录。只有当前所选流程确实需要处理 SSH 身份时，才会创建或修改 `~/.ssh`，并且会在创建前明确显示新增私钥和主机名。私钥不会复制到中央项目或 `private/config.txt`。普通推送绝不使用强制覆盖。历史导入始终保持原始发布文件夹不变。

## 运行要求和测试

- Bash 3.2 或更高版本。
- Git 与 OpenSSH 工具：`git`、`ssh`、`ssh-keygen`。
- 单文件 Bash 引擎使用的标准 POSIX/macOS 工具。
- 连接 GitHub 以验证身份和仓库权限的网络环境。

运行隔离测试：

```bash
./tests/test.sh
```

测试使用临时用户目录、私人配置、Git 仓库、SSH 配置和模拟 SSH 传输，不会读取真实私人配置，也不会改动真实 GitHub 仓库。
